# Worked example: a Tallyhouse patio-season campaign

Tallyhouse is a fictional restaurant bookkeeping firm. The files:
- `requests/patio-slack.md`: the request, a short Slack thread from Hannah Ruiz
- `brand/`: the parts of brand memory the intake reads
- `intake/patio-season.md`: the intake
- `reply.md`: the reply to the person who asked

## What the intake decided

| Request said | Intake | Why |
|---|---|---|
| "$1,500 a month, March and April" | `1500 per month … 3000 total; currency assumed CAD` | Budgets are digits. The currency wasn't stated, so it's an assumption to confirm, not a fact |
| "Live March 2" | `Deadline: 2027-03-02` | A date with no year resolves to the next March 2 after today |
| "Cut your labour costs by 15%" | Kept out of the fields, listed under Claims with what would clear it | No source in brand memory or the request. Confirmed facts are offered instead; no replacement figure is made up |
| Owners in BC and Ontario | Matched to the 1–15 location segment | The request fits a brand memory segment, so the intake quotes it |
| Nothing on where bookings are counted | `assumed: … (confirm: Hannah)` | A safe default exists, so it's an assumption, not a question |

## Why no questions

Every open item has a safe default or can be carried by the next step as a gap. None changes the audience, offer, channels, budget or date, so the reply asks nothing and lists the assumptions in one line.
