## How to use this

1. If the user lists the skills they have installed, match only to those. A better fit that isn't installed goes in the `library_skills` column as `(not installed: name)` and is never described as something they have.
2. Otherwise, use the live library index (the `library` command lists every skill that exists, with its description). Recommend only skills that index shows as built.
3. If neither is available, use the table below.
4. One to three skills per task, the ones that do the task's actual job. Don't attach a skill because its topic is nearby.

## Task type to skill

| Task type | Skill | What it does for the task |
|---|---|---|
| Keeping facts, prices, proof and rules in one place | brand-memory | The `brand/` folder every other skill reads |
| Writing down how the brand sounds | brand-voice-codify | A voice guide from real samples |
| Making a draft sound human and on-brand | de-slop, brand-voice-gate | Removes AI tells; applies voice and claims rules |
| Briefing a blog post, guide or page | content-brief | A brief with audience, must-includes, CTA and keyword |
| Final check before publishing | content-qa-gate | Publish / Fix first / Hold, with every problem located |
| Collecting and resolving reviewer comments | editorial-review-cycle | A review packet and a revised draft |
| Deciding what to keep, update or remove in a content library | content-audit | A keep / update / merge / redirect / remove list |
| Newsletters and lifecycle email | email-sequence | Sequences with timing, subject lines and consent basis |
| LinkedIn posts | linkedin-content | Posts in a named person's voice |
| Cold and warm outbound to prospects | reach-out | Sourced drafts staged for a person to approve |
| Sorting and answering replies to outbound | handle-reply | Replies, holds and opt-outs |
| Building and scoring prospect lists | build-list, icp | Scored account lists; the customer profile behind them |
| Mapping a buying committee | map-contacts | Roles and who to contact first |
| Tracking competitors' pages and pricing | competitor-intel | Dated profiles and a battlecard |
| Google Ads checks and builds | google-ads-audit, google-ads-build | A scored audit; an importable campaign |
| Meta ads checks and builds | meta-ads-audit, meta-ads-build | A scored audit; a campaign ready to load |
| Website reviews | marketing-audit, audit-positioning, audit-acquisition, audit-conversion, audit-brand, audit-measurement | Scored reports with a 48-hour / 2-week / 3-month plan |
| Claims, disclosures and accessibility | claims-review, disclosure-check, accessibility-review | Risk-rated issues with fixes |
| Turning a process that works into a reusable skill | skill-author | A skill that meets the Bench Standard |

The library index is the authority on what exists. A skill named in a pack but not built yet is not recommended.

## When nothing fits

Write nothing in `library_skills` and, in the map's Library skill column, "None in the library: a general AI assistant with <inputs>". Never make up a skill name, and never describe a recurring report or translation as covered by a skill whose description doesn't mention it.
